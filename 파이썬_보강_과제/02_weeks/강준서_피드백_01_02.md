## 1. 사실 확인 — 제출 파일 실행 결과

| 파일 | 실행 결과 | 기댓값 | 판정 |

문법 에러 없음, 함수 중복 정의 없음, 제한 기능(`get`, `zip`, 슬라이싱) 미사용. 경계 입력도 확인해 봤는데 전부 통과합니다.

## 2. 이번 주 가장 잘하신 것 — `[5] 직접 넣어본 추가 입력`

새로 생긴 칸인데, 준서 님은 **두 문제 다 채우셨습니다.** 그리고 채운 방식이 정확히 의도한 대로입니다.

```
# 내가 만든 입력 | 그렇게 만든 이유 | 예상 결과 | 실제 결과
# [('tea', 0)] | 판매 금액은 0 이상의 정수라고 해서 0도 넣어봄 | {'tea': 0} | {'tea': 0}
# [10, 10, 10] | 전날과 기온이 같은 날은 오른 날이 아니라고 하길래 | 0 | 0
```

**"~라고 해서", "~라고 하길래"** — 지문의 조건 문장을 근거로 입력을 만드셨습니다. 이게 이 칸의 목적입니다.

이게 왜 중요하냐면, 1주차에 다섯 명 중 한 분이 정확히 이 지점에서 걸렸기 때문입니다. 지문에 *"0 이상의 정수"* 라고 적혀 있었는데 그 조건에서 입력을 안 만들어서, 예시 세 개를 통과하면서도 `[12000, 0, 8500]` 에서 틀리는 코드를 제출했습니다.

준서 님은 이번에 `[('tea', 0)]` 을 직접 만들어 넣으셨고, 그래서 그 종류의 버그가 없다는 걸 **본인이 확인한 상태**로 제출하셨습니다.

> **한 가지만 더.** 
>
> 지금은 예상 결과와 실제 결과가 둘 다 맞아서 이 칸이 "확인"으로만 쓰였습니다.
> 다음엔 **예상과 실제가 다른 입력을 일부러 하나 만들어 보세요.**
> 예를 들어 02번에서 `range(1, ...)` 을 `range(0, ...)` 으로 바꾼 뒤 `[30, 10]` 을 넣으면 답이 `1`로 바뀝니다. 그때 이 칸이 "확인"이 아니라 **"발견"** 이 됩니다.

## 3. 결정적인 지점

정답을 이미 쓰셨는데 그걸 답으로 인정하지 않으셨습니다

여기가 이번 피드백의 본론입니다. 02번 설계 [3] 0번 칸입니다.

```python
# 0. [반복을 몇 번 인덱스부터 시작할 것인가] 0번 인덱스
#    [왜] 0번 인덱스가 첫번째 값이고 두번째 값이랑 비교를 해야하기 때문에
#         아 1번인덱스부터봐야하나요? 바로 전날이랑 비교를 하려면 전날 온도가
#         있어야 하는데 0은 이전 온도가 없는데
```

**두 번째 줄이 정답입니다.**

> *"바로 전날이랑 비교를 하려면 전날 온도가 있어야 하는데 0은 이전 온도가 없는데"*

이 문장은 이 문제 해설에 적힌 것과 사실상 같은 설명입니다. 아무도 안 알려줬는데 준서 님이 쓰셨어요. **글을 쓰다가 스스로 발견하신 겁니다.**

그런데 그다음이 문제입니다.

- 위에 적어둔 답 `0번 인덱스` 를 **고치지 않으셨습니다**
- 그리고 회고에는 이렇게 쓰셨습니다

```python
# 막힌 지점 : for t in range(1, len(temps)): if temps[t] > temps[t - 1]:
```

**본인이 3분 전에 쓴 문장이 그 막힌 지점의 답이었습니다.**



### 3-1. 이건 1주차에도 있었던 패턴입니다

1주차 피드백 3장에 이렇게 썼습니다.

> 손으로 표를 그릴 때 준서 님은 "첫 번째 값을 잠정 1등으로 놓는다"를 이미 정확히 하고 계십니다.
> 그런데 그 직관이 코드로 넘어가는 순간 사라집니다.

이번엔 표가 아니라 **글**에서 같은 일이 일어났습니다.

| | 정답을 쓴 곳 | 그런데 |
|---|---|---|
| 1주차 | 손 추적표의 `시작` 줄 (`21`, `85`) | 코드에는 `total = 0`, `highest = 1` |
| 2주차 | 설계 [3] 0번 칸의 두 번째 줄 | 위에 적은 답은 `0번 인덱스` 그대로 |

**두 번 다 "내가 쓴 것"을 "내 답"으로 안 세신 겁니다.**

*"아 1번인덱스부터봐야하나요?"* 이 물음표가 문제입니다. 준서 님 문장을 그대로 읽으면 이미 근거까지 다 들어 있는 **평서문**입니다. *"전날이랑 비교하려면 전날 온도가 있어야 한다. 0번은 이전 온도가 없다. 따라서 1번부터 시작한다."*

> **다음 과제부터 규칙 하나를 추가하세요.**
> **설계 칸을 쓰다가 "아 혹시 ~인가요?" 라는 문장이 나오면, 거기서 멈추고 그 문장을 위 칸에 답으로 옮겨 적으세요.**
> 그리고 그게 맞는지 실제로 돌려서 확인하세요. 
> 물음표를 평서문으로 바꾸는 것, 그게 이번 주에 준서 님이 해야 할 유일한 일입니다.

> **역질문 1.**
> `range(1, len(temps))` 와 `range(0, len(temps))` 를 각각 넣고 `[30, 10]` 을 돌려 보세요.
> 답이 다르게 나옵니다. **왜 다른지** 한 문장으로 적어보세요.
> (힌트: `temps[0 - 1]` 은 에러가 아닙니다. 파이썬에서 `-1` 은 무엇을 가리키나요?)

## 4. 손 추적표가 회고의 질문에 이미 답하고 있습니다

02번에서 GPT 코드를 받은 뒤 이렇게 적으셨습니다.

```python
    for t in range(1, len(temps)): #len(temps) : ... 그럼 range(1, 5)가 됨.. 근데 왜 이렇게 하는거지?
        if temps[t] > temps[t - 1]: # 이렇다는데 지피티를 봐도 이해가 잘 안됨;;.,,
                                    # 이렇게 range를 하면 범위가 1부터 4까지만 되는건데
                                    # 그럼 0이 아예 없는데..
```

**"0이 아예 없는데.."** — 이게 준서 님이 진짜로 막힌 지점입니다. 그런데 바로 아래 손 추적표를 보세요. 준서 님이 직접 그리신 표입니다.

```
# 회차 | 인덱스 | 전날 기온 | 오늘 기온 | 올랐나 | count
# 1   |   1   |    21    |    25    | True  | 1     <- 여기!
```

**1회차의 '전날 기온' 칸에 `21`이 들어가 있습니다.** `21`은 인덱스 0번의 기온이죠.

즉 **0번은 "없는" 게 아니라, `오늘 기온` 칸이 아니라 `전날 기온` 칸에 들어가 있습니다.**

정리하면 이렇습니다.

| 인덱스 0의 역할 | 표에서 어디에 있나 |
|---|---|
| **오른 날 후보**로 판정받는 대상 | 없음 (첫날은 비교할 전날이 없으니까) |
| **다음 날의 비교 기준** | 1회차의 `전날 기온` 칸 = `21` |

`range(1, 5)` 가 "0을 버린다"는 뜻이 아닙니다. **"0번은 판정 대상이 아니라 비교 재료다"** 라는 뜻입니다. 그리고 준서 님 표에서 `21`은 실제로 쓰이고 있습니다. 다만 `오늘 기온` 자리가 아니라 `전날 기온` 자리에서요.



### 4-1. 그래서 이번에도 순서가 뒤집혀 있었습니다

준서 님은 표를 **코드를 받은 뒤에** 그리셨을 가능성이 큽니다. 표가 GPT 코드와 정확히 일치하거든요 (인덱스 1부터 4까지, 4행).

만약 표를 **먼저** 그리셨다면 이렇게 됐을 겁니다.

1. `[21, 25, 23, 23, 30]` 을 손으로 따라간다
2. 1회차에 비교할 두 값이 `21` 과 `25` 라는 걸 적는다
3. **"어? 21은 0번인데 오늘 기온이 아니라 전날 기온 자리에 들어가네"** 를 발견한다
4. 그러면 반복은 1번부터 돌면 된다는 게 나온다

**표가 곧 답입니다.** 1주차 피드백에서 "손 추적표는 검산 도구가 아니라 설계 도구"라고 말씀드린 게 이 뜻입니다. 이번에도 표는 정확하게 그리셨어요. **순서만 바꾸시면 됩니다.**

## 5. 문제별 상세 피드백

### 문제 01 — `sum_sales_by_category`

**결과: 정답. 제한 기능(`get`) 미사용.**

```python
def sum_sales_by_category(records):
    result = {}
    for category, price in records:
        if category in result:
            result[category] = result[category] + price
        else:
            result[category] = price
    return result
```

#### 1트를 먼저 봅니다

```python
#[1트]
# def sum_sales_by_category(records):
#     result = {}
#     for category, price in records: # 여기서 막힘. records는 category, price로
#                                     # 이어져 있어서 저렇게 두개를 꺼낸다 까지는 생각을 해봄
#         # 여기에 if문을 어떻게 써야할지 잘 모르겟다...
```

**여기서 두 가지를 짚고 싶습니다.**

첫째, `result = {}` 를 **혼자 쓰셨습니다.** 1주차 04번에서 *"`result = []` 이걸 지정할 생각조차 못했음. 그리고 왜 지정해야하는지 감도 못잡았음"* 이라고 쓰셨던 걸 기억하시나요? 

그리고 [3] 0번 칸의 근거가 정확합니다.

```
#    [왜] + []이나 0이라고 하지 않는 이유 : 문자열을 키로 사용해야하기 때문에.
#         0은 숫자를 누적할때 사용, []은 값을 순서대로 모을 때 사용
```

**세 가지 시작값을 나란히 놓고 구분하셨습니다.** 1주차에 "변수는 세는 그릇 한 종류뿐"이라고 지적했던 그 자리입니다. 이번엔 그릇이 세 종류가 됐어요.

둘째, `for category, price in records:` 를 **혼자 쓰셨습니다.** 튜플 언패킹입니다. 1주차 04번에서는 `item[1]` 을 쓰셨고 `result = []` 를 못 떠올리셨는데, 이번엔 시작값과 언패킹을 둘 다 혼자 하셨습니다.

**막힌 건 딱 `if` 문 하나였습니다.** 나머지는 다 짜신 겁니다. 이건 1주차 03번에서 *"막힌 지점: 처음부터 끝까지"* 라고 쓰셨던 것과 완전히 다른 상태입니다.



#### GPT 코드에 단 주석이 훌륭합니다

```python
            result[category] = result[category] + price
            # total = total+score ->이런거랑 원리는 똑같다.
            # 대신, coffee라는 누적 공간에 계속 더하는 것일 뿐임
```

**"원리는 똑같다"** — 1주차 01번의 누적 골격과 이 문제를 연결하셨습니다.

이게 정확히 맞습니다. 이 문제 해설에도 같은 이야기가 적혀 있어요.

> 더하는 동작(`total += price`)은 완전히 같다. 달라진 건 '어디에 더하는가'뿐이다.
> `result[category] += price` 의 `result[category]` 가 1주차의 `total` 자리에 해당한다.

1주차 피드백에서 준서 님 골격 어휘가 "누적" 하나뿐이라고 지적했는데, 그때는 그게 약점이었습니다. **이번엔 그 하나를 정확한 자리에 쓰셨습니다.** 새 문제를 새 유형으로 안 보고 **아는 골격의 변형으로 본 것**이니까요. 이게 유형 3(유형 암기)에서 벗어나는 방식입니다.



#### 짚을 것

**[3] 설계 2번, 3번 칸이 비어 있습니다.**

```python
# 2. [무엇을]
#    [왜] 카테고리를 하나씩 꺼내서 dict에 누적해야하는데, 반복문을 통해서
#         category랑 price값을 각각 꺼내고도 어떻게 누적해야하는지 모르겟다
#
# 3. [무엇을]
#    [왜]
```

**푸시기 전에는 이렇게 비어 있는 게 맞습니다.** 모르는 걸 모른다고 쓰신 거니까요.

다만 **답을 알아낸 뒤에 돌아와서 채우셔야 합니다.** 지금 준서 님은 답을 아십니다. GPT 코드 옆에 정확한 주석까지 다셨고요. 그 주석을 2번 칸으로 옮겨 적으면 이렇게 됩니다.

```python
# 2. [무엇을] 이미 있는 분류면 기존 값에 price를 더하고, 처음 보는 분류면
#             price를 그대로 넣는다.
#    [왜]     딕셔너리는 없는 키에 바로 더할 수 없다.
#             result[category] + price 를 계산하려면 왼쪽 값을 먼저 읽어야 하는데,
#             키가 없으면 읽을 게 없어서 KeyError가 난다.
#             그래서 '있는지 먼저 확인한다'가 필요하다.
```

코드 옆 주석은 다음 주에 이 파일을 열면 안 보입니다. 양식 칸은 남습니다.

**회고의 "예측과 실제가 달랐던 곳"이 비어 있습니다.**

1주차 피드백에서 이 칸을 다섯 명 중 한 명만 제대로 채웠다고 말씀드렸는데, 준서 님은 02번에서는 채우셨습니다.

```python
# 예측과 실제가 달랐던 곳 : 1트째 for t in temps: 이렇게 했을 때 당연히 값이
```

**01번에도 쓸 게 있었습니다.** *"`for category, price in records` 까지는 됐는데 `if` 를 어떻게 쓸지 몰랐다. 알고 보니 '없는 키는 읽을 수 없다'가 이유였다"* 정도면 충분합니다.

### 문제 02 — `count_rising_days`

**결과: 정답. 제한 기능(`zip`, 슬라이싱) 미사용.**

3장과 4장에서 핵심을 다뤘으니 여기서는 나머지를 짚습니다.

#### 추가 질문 답변이 정확합니다

```
# 답 : 이 문제에서는 현재 기온이랑 그 전날 기온을 비교함.
#      고정된 값이랑 비교하는게 아니라 바뀌는 값을 누적?해서 비교해야댐
```

*"고정된 값이랑 비교하는게 아니라 바뀌는 값"* — **이 문제의 출제 의도를 정확히 짚으셨습니다.** 1주차 02번은 `'late'` 라는 고정값과 비교했고, 이 문제는 기준이 매 회차 움직입니다.

(다만 "누적해서"는 조금 다릅니다. 값을 쌓는 게 아니라 **매번 새 짝과 비교**하는 거예요. "바뀌는 값과 비교"까지가 정확한 표현입니다.)

#### 1트와 2트를 해부해 봅니다

**1트**

```python
# def count_rising_days(temps):
#     for t in temps:
#         if temps[t] > temps[t-1]: #여기서 오류남
```

`for t in temps` 로 쓰면 `t` 에는 **기온 값**(21, 25, ...)이 들어갑니다. 그걸 `temps[t]` 처럼 인덱스 자리에 쓰면 `temps[21]` 을 찾게 되고, 원소가 5개뿐이라 `IndexError` 가 납니다. 실제로 돌려보니 그렇게 나옵니다.

**2트**

```python
#     for [t] in temps:
```

여기서는 `TypeError: cannot unpack non-iterable int object` 가 납니다. `for [t] in ...` 은 "원소를 하나씩 꺼내되, 그 원소를 다시 쪼개서 `t` 에 담아라"는 뜻이거든요. 01번의 `for category, price in records` 와 같은 문법입니다. 그런데 `temps` 의 원소는 정수 `21` 이라 쪼갤 게 없습니다.

**이 두 오류가 사실은 한 가지를 가리킵니다.**

> **`for` 문의 반복 변수에 무엇이 담기는지를 먼저 정해야 한다.**

- `for temp in temps` => `temp` 에 **값**이 담긴다 (21, 25, ...)
- `for i in range(len(temps))` => `i` 에 **인덱스**가 담긴다 (0, 1, 2, ...)

그리고 어느 쪽을 쓸지는 하나로 결정됩니다. **인덱스가 필요한가?**

이 문제는 `temps[i - 1]` 로 전날을 찾아야 하니 인덱스가 필요합니다. 그래서 두 번째 형태를 씁니다.



#### 그런데 이 판단을 하라고 만든 칸이 비어 있습니다

```
# [2] 변수 역할표
# 변수 이름 | 담기는 것 | 시작값 | 그 시작값이어야 하는 이유
#   count | 전날보다 기온이 오른 날의 개수 | 0 | 처음에는 하나도 안세서
#          |          |       |            <- 비어 있음
```

**`count` 만 적고, `t` 를 안 적으셨습니다.** 그런데 준서 님이 1트와 2트에서 막힌 게 정확히 `t` 입니다.

이 칸을 채웠다면 이런 순서가 됐을 겁니다.

1. `t` 라는 변수를 만들 건데, 여기 담기는 게 뭐지?
2. `temps[t - 1]` 로 전날을 찾아야 하니까 **인덱스**다
3. 인덱스를 담으려면 `for t in temps` 가 아니라 `for t in range(...)` 를 써야 한다

**세 줄 만에 1트와 2트를 건너뛰게 됩니다.** 문제 파일에도 이 안내가 적혀 있었습니다.

```
# 특히 i 라는 이름은 '인덱스'가 담길 때만 쓰세요.
```

역할표는 형식 절차가 아니라, **1트를 미리 막기 위한 칸**입니다. 다음 과제에서는 만들 변수를 하나도 빠뜨리지 말고 전부 적어 주세요.

> **역질문 2.**
> 준서 님 최종 코드의 반복 변수 이름은 `t` 입니다. 담기는 건 인덱스고요.
> 그런데 1트에서는 같은 `t` 에 기온 값을 담으셨습니다.
> **이름을 `t` 대신 무엇으로 바꾸면, 1트와 3트의 차이가 이름만 보고도 구분될까요?**
> (힌트: 값이면 `temp`, 인덱스면 `i` 또는 `idx`)



#### 손 추적표는 정확합니다

```
# 회차 | 인덱스 | 전날 기온 | 오늘 기온 | 올랐나 | count
# 1   |   1   |    21    |    25    | True  | 1
# 2   |   2   |    25    |    23    | False | 1
# 3   |   3   |    23    |    23    | False | 1
# 4   |   4   |    23    |    30    | True  | 2
```

4행 전부 맞습니다. 특히 3회차의 `23 vs 23` 을 `False` 로 적으신 게 좋습니다. 지문의 *"전날과 기온이 같은 날은 '오른 날'이 아니다"* 를 표에 반영하신 거고, 그게 `>=` 가 아니라 `>` 를 쓴 근거입니다.

그리고 **값이 안 바뀐 회차의 `count` 칸도 이전 값을 그대로 다시 적으셨습니다.** (2회차와 3회차의 `1`) 1주차에 이걸 비워두거나 `0`으로 되돌린 학생들이 있었는데, 준서 님은 정확히 하셨어요.

## 6. 이 과제의 핵심 (Key Takeaway)

> **1. 설계 칸에 "아 혹시 ~인가요?" 가 나오면, 그 문장이 답이다.**
> 02번에서 *"바로 전날이랑 비교를 하려면 전날 온도가 있어야 하는데 0은 이전 온도가 없는데"* 라고 쓰셨고, 그게 정답이었습니다. 물음표를 지우고 위 칸에 옮겨 적으세요.
>
> **2. `for` 문을 쓰기 전에 "반복 변수에 값이 담기나 인덱스가 담기나"를 먼저 정한다.**
> 판단 기준은 하나입니다. **인덱스가 필요한가?** 필요하면 `range`, 아니면 값으로 돕니다. 역할표 [2]번 칸이 이 판단을 하는 자리입니다.
>
> **3. 시작값은 반환할 것의 종류가 결정한다.**
> 숫자면 `0`, 목록이면 `[]`, 분류별이면 `{}`. 준서 님이 01번 [왜] 칸에 직접 쓰신 문장입니다.

## 7. 당장 시도해 볼 것

1. **02번을 `range(0, len(temps))` 로 바꿔서 `[30, 10]` 을 넣어 보세요.** 답이 `1`로 바뀝니다 (정답은 `0`). `temps[0 - 1]` 이 마지막 원소를 가리키기 때문인데, **에러가 안 나서 조용히 틀립니다.** 이걸 눈으로 보시면 `range(1, ...)` 의 이유가 확정됩니다.
2. **02번 설계 [3] 0번 칸의 답을 `1번 인덱스` 로 고쳐 쓰세요.** 그리고 이유는 준서 님이 이미 쓰신 그 문장을 그대로 쓰시면 됩니다. 물음표만 빼고요.
3. **02번 [2] 역할표에 `t` 를 추가하세요.** 담기는 것은 `인덱스`, 시작값은 `1`, 이유는 `0번은 비교할 전날이 없어서`. 그리고 이름을 `i` 로 바꾸세요.
4. **01번 설계 [3] 2번 칸을 채우세요.** 지금 답을 아시니 채울 수 있습니다. GPT 코드 옆에 다신 주석을 옮겨 적으면 됩니다.
5. **01번 회고의 "예측과 실제가 달랐던 곳"을 채우세요.** 1트에서 `if` 를 못 쓴 것과, 그 이유가 "없는 키는 읽을 수 없다"였다는 걸 적으시면 됩니다.
6. **02번을 백지에서 다시 한 번 짜 보세요.** GPT 코드도 1트도 보지 말고요. 지금은 답을 아시니, 이번엔 **손이 기억하는지**를 확인하는 겁니다.
7. **이 문서의 역질문 2개**(3장 / 02번)에 각각 한두 문장씩 답을 적어 오세요. 면담 때 이걸로 이야기하겠습니다.

## 8. 마지막으로

한 주 전 피드백에서 준서 님께 이렇게 썼습니다.

> 지금 겪는 막막함은 실력이 부족해서가 아닙니다. 번역 훈련을 아직 안 한 것입니다.
> 손 추적표에서 이미 맞는 답을 쓰고 계신 걸 보면, 번역할 원문은 이미 준서 님 머릿속에 있습니다.

이번 제출물이 그걸 다시 확인시켜 줍니다. 01번에서 `result = {}` 와 튜플 언패킹을 혼자 쓰셨고, 02번에서는 "0번은 이전 온도가 없다"는 정답 문장을 혼자 쓰셨습니다. 

그런데 두 번 다 마지막 한 걸음에서 멈추셨어요. 01번은 `if` 하나를 못 채워서, 02번은 자기가 쓴 문장을 답으로 안 세워서요.

**그 한 걸음의 정체가 이번에 좀 더 분명해졌습니다.**

제출물을 보면 물음표가 아주 많습니다. *"분류별?"*, *"빈 dict로 시작?"*, *"세는 문제여서?"*, *"누적?해서"*, *"1번인덱스부터봐야하나요?"* — 그런데 이 물음표들 뒤에 붙은 내용은 **거의 다 맞습니다.**

맞는 답을 쓰면서 확신이 없으신 겁니다. 그리고 확신이 없으니까 GPT에 확인을 받으러 가시고, 확인을 받고 나면 그게 **"내가 알아낸 것"이 아니라 "GPT가 알려준 것"** 으로 기록됩니다. 02번 회고에 *"막힌 지점: `for t in range(1, len(temps))`"* 라고 쓰신 게 그 결과예요. 사실 그건 준서 님이 이미 답을 쓴 지점이었는데요.

그래서 이번 주에는 딱 하나만 해보세요.

> **설계 칸을 쓰다가 물음표가 나오면, GPT에 물어보기 전에 그 문장이 맞는지 코드로 먼저 확인한다.**

`[30, 10]` 을 넣어 보는 데 몇초 안걸립니다. 그 넣어보는 시간이 "GPT가 알려준 것"을 "내가 확인한 것"으로 바꿉니다. 그리고 그 차이가 평가에서 전부입니다.
