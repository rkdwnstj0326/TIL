**"나는 각 인덱스 번호에 할당된 숫자가 나온다고 생각했음"** — 이게 정확한 자가 진단입니다. 무엇을 틀렸는지가 아니라 **무엇을 잘못 알고 있었는지**를 쓰셨어요.

정리하면 이렇습니다.

| | 반복 변수에 담기는 것 | 값을 꺼내려면 |
|---|---|---|
| `for i in profits:` | **값** (10, 30, 20, ...) | `i` 를 그냥 쓴다 |
| `for i in range(len(profits)):` | **인덱스** (0, 1, 2, ...) | `profits[i]` 로 꺼낸다 |

그리고 어느 쪽을 쓸지는 하나로 결정됩니다. **인덱스가 답에 필요한가?**

04번은 "경신한 주의 인덱스"를 반환해야 하니 인덱스가 필요합니다. 그래서 두 번째 형태를 쓰신 게 맞습니다.

> **역질문 1.**
> 03번 코드에서는 `for i in range(1, len(temps))` 를 쓰셨고, 04번에서는 `for i in range(0, len(profits))` 를 쓰셨습니다.
> **한쪽은 1부터, 한쪽은 0부터인데 둘 다 맞습니다.** 왜 그럴까요?
> (힌트: 두 문제의 `result` 시작값을 나란히 놓고 보세요)



### 2-3. `return` 위치도 스스로 잡으셨습니다

1트에는 이런 줄이 있었습니다.

```python
            return result.append(i)
```

그리고 2트 주석에 이렇게 적으셨죠.

```python
            result.append(i) #반복이 전부 끝난 뒤에 return을 해야하는데 return과 result를 같이 써버림.;;;
```

**1주차 04번, 05번에서 세 번 반복하셨던 그 실수입니다.** 그때는 4트까지 가서야 잡으셨고, 이번엔 1트에서 2트로 넘어가면서 바로 잡으셨습니다.

한 가지만 덧붙이면, `return result.append(i)` 는 **두 가지가 동시에 잘못됐습니다.**

1. 반복문 안에 `return` 이 있어서 첫 회차에 함수가 끝난다
2. `append()` 는 **아무것도 돌려주지 않는** 메서드라, `return append(...)` 는 `None` 을 반환한다

`append` 는 리스트를 "바꾸기만" 하고 결과를 내놓지 않습니다. 그래서 `result = result.append(i)` 같은 것도 쓰면 안 됩니다. `result` 가 `None` 이 되어 버리거든요.

여기가 이번 피드백의 본론입니다. 그리고 **1주차부터 세 주 연속 같은 이야기**입니다.

### 3-1. 03번 — 표는 4회, 코드는 3회

준서 님이 그리신 표입니다.

```
# 회차 | 인덱스 | 꺼낸 값 | 처리 | 최고 기온 | 인덱스 목록
# 시작 |   -   |   -    |  -  |    21    |   [0]
# 1   |   0   |   21   | x   |    21    |   [0]      <- 인덱스 0부터
# 2   |   1   |   25   | 갱신 |    25    |   [1]
# 3   |   2   |   25   | 추가 |    25    |   [1, 2]
# 4   |   3   |   19   | x   |    25    |   [1, 2]
```

그런데 코드는 이렇습니다.

```python
    for i in range(1, len(temps)):   # <- 인덱스 1부터. 3회만 돕니다
```

**표는 인덱스 0부터 4회, 코드는 인덱스 1부터 3회입니다.**

이 선택 자체는 정확합니다. 0번은 이미 시작값(`high = temps[0]`, `result = [0]`)으로 처리했으니 건너뛰는 게 맞아요. 다만 **표와 코드가 서로 다른 이야기를 하고 있습니다.**

표의 1회차를 보시면 `21` 을 꺼내서 `21` 과 비교하고 `x` 라고 적으셨죠. **자기 자신과 비교하는 회차**입니다. 표를 그리면서 "어? 이건 이미 처리한 값인데?" 하고 느끼셨다면, 그게 곧 `range(1, ...)` 의 이유가 됩니다.



### 3-2. 05번 — 표는 지점이 끝날 때만 평균, 코드는 매 회차 평균

준서 님이 그리신 표입니다.

```
# 바깥 | 안쪽 | 순이익 | 지점 합계 | 지점 개월수 | 지점 평균 | 최고 평균 | 최고 지점 번호
# 1   |  1  |   80  |    80    |     1      |    -     |    -     |      -     <- 평균 없음
# 1   |  2  |   90  |   170    |     2      |    85    |    85    |      0     <- 여기서 평균
# 2   |  1  |  100  |   100    |     1      |   100    |   100    |      1
# 3   |  1  |   70  |    70    |     1      |    -     |   100    |      1     <- 평균 없음
# 3   |  2  |   75  |   145    |     2      |    -     |   100    |      1     <- 평균 없음
# 3   |  3  |   95  |   240    |     3      |    80    |   100    |      1     <- 여기서 평균
```

**문제 없습니다.** 지점의 마지막 달에만 평균이 나오고, 중간 회차는 `-` 입니다. 그리고 최고 평균과 최고 지점 번호까지 정확합니다.

그런데 코드는 이렇습니다.

```python
        for i in branch:
            i_sum = i_sum + i
            count = count + 1

            avg = i_sum / count      # <- 안쪽 for '안'. 매 회차 계산됨
```

**`avg` 가 안쪽 반복문 안에 있습니다.** 표에서는 `-` 로 비워 둔 자리에서도 평균이 계산되는 겁니다.

`[[80, 90], [100], [70, 75, 95]]` 로 따라가면 이렇게 됩니다.

| 회차 | 표에 적으신 평균 | 코드가 계산하는 평균 |
|---|---|---|
| 1지점 1달 | `-` | `80.0` |
| 1지점 2달 | `85` | `85.0` |
| 3지점 1달 | `-` | `70.0` |
| 3지점 2달 | `-` | `72.5` |
| 3지점 3달 | `80` | `80.0` |

**표는 2개인데 코드는 6개를 만듭니다.** 그리고 그 중간 평균들도 비교 대상이 되어 버립니다.



### 3-3. 이게 왜 문제가 되는가

지금은 막혀 있어서 비교하는 부분이 없지만, 그 자리를 채우고 나면 문제가 드러납니다. 확인해 봤습니다.

| 입력 | 지점별 평균 | `avg` 가 안쪽일 때 | 정답 |
|---|---|---|---|
| `[[80, 90], [100], [70, 75, 95]]` | 85 / 100 / 80 | `1` | `1` |
| `[[50, 50], [40, 60]]` | 50 / 50 | `0` | `0` |
| `[[-10, -20], [-5]]` | -15 / -5 | `1` | `1` |
| **`[[100, 0], [60]]`** | **50 / 60** | **`0`** | **`1`** |

**주어진 예시 네 개는 전부 통과하고, `[[100, 0], [60]]` 에서 틀립니다.**

이유는 이렇습니다. 0번 지점의 첫 달 순이익이 `100` 인데, 그 시점의 중간 평균도 `100` 입니다. 그게 최고 기록으로 잡히고, 1번 지점의 `60` 은 그걸 못 넘죠. **하지만 0번 지점의 진짜 평균은 `50` 입니다.**

> **평균은 그 지점을 끝까지 다 봐야 나옵니다.**
> 그래서 `avg = i_sum / count` 는 **안쪽 `for` 가 끝난 뒤**, 바깥 `for` 안에 있어야 합니다.
> 들여쓰기 한 칸이 '언제 계산하는가'를 결정합니다.

**그리고 준서 님 표에는 그게 이미 그려져 있습니다.** 중간 회차의 평균 칸을 `-` 로 비워 두신 게 정확히 그 뜻입니다.

## 4. 05번 

막힌 건 개념 하나였습니다

05번은 미완성이지만, **어디까지 갔는지가 아주 분명하게 남아 있습니다.**

### 4-1. 설계는 다 하셨습니다

```python
# [내생각]
# branches에서 인덱스 하나씩 꺼냄 반복문으로
# branch안에 있는 값들을 더해서 평균을 낸다 -> 근데 어떻게 더하고 평균을 내지?
# 더한걸 하나 만들고, 개수를 세는걸 하나 만들어야댐. 그래야 나눠서 평균을 낼 수 잇나 > 근데 이걸 어케하지
# 각 평균중에서 제일 평균이 큰 인덱스 번호를 반환한다.
#   평균이 똑같으면 앞 인덱스 번호를 반환한다.
```

**다섯 줄로 이 문제를 전부 설계하셨습니다.** 그리고 실제로 그대로 코드를 짜셨어요.

- *"더한걸 하나 만들고"* => `i_sum = 0`
- *"개수를 세는걸 하나 만들어야댐"* => `count = 0`
- *"그래야 나눠서 평균을"* => `avg = i_sum / count`

**"근데 이걸 어케하지"라고 쓰신 것을 바로 아래에서 해내셨습니다.** 1주차에 *"막힌 지점: 처음부터 끝까지"* 라고 쓰셨던 것과 비교하면 완전히 다른 상태입니다.

```
# 0-3. [최고 평균 지점의 번호 변수 - 시작값] 잘 모르겟음
```

**모르는 걸 모른다고 쓰신 게 맞습니다.** 그리고 막힌 지점이 정확히 이 두 칸입니다.



### 4-3. 그런데 이건 04번에서 이미 하신 것입니다

04번 코드를 다시 보세요.

```python
def find_record_weeks(profits):
    high = profits[0]        # <- 비교할 상대
    result = [0]
    for i in range(0, len(profits)):
        if profits[i] > high :      # <- 지금 값과 '지금까지의 최고'를 비교
            high = profits[i]       # <- 이겼으면 최고를 갈아치운다
            result.append(i)
    return result
```

**`high` 가 정확히 05번에서 못 만드신 그 변수입니다.**

05번에서 필요한 건 `high` 두 개예요.

- 지금까지의 최고 **평균** (04번의 `high` 와 같은 역할)
- 그 평균을 낸 **지점 번호** (04번에는 없던 것. 값과 위치를 짝으로 들고 다녀야 하니까)

그리고 시작값을 정하는 방법도 04번과 같습니다. **04번에서 `high = profits[0]` 이라고 쓰신 이유를 그대로 적용하면 됩니다.**

```
# 04번 [2] 역할표에 준서 님이 쓰신 것
#  high | 역대 최고 순이익 | profits[0] | profits 리스트의 0번째 값을 가져와서 시작값으로 삼기 위해서
```

*"0번째 값을 가져와서 시작값으로 삼는다"* — 05번에서도 같습니다. 다만 0번째 **지점의 평균**이라서, 그 평균을 먼저 계산해야 한다는 점만 다릅니다.

그게 번거로우면 이런 방법도 있습니다.

```python
    idx = 0
    for branch in branches:
        ...
        if idx == 0 or avg > best_avg:    # 첫 지점은 무조건 최고로 잡는다
            best_avg = avg
            best_idx = idx
        idx += 1
```

**"첫 회차는 비교 대상이 없으니 무조건 확정"** 이라는 처리인데, 04번의 `result = [0]`(1주차는 무조건 경신)과 같은 발상입니다. 준서 님이 04번 역할표에 이렇게 쓰셨죠.

```
# result | ... | [0] | 1주차는 무조건 경신한 주라고 했기 때문임(비교할 값이 없기 때문에 그냥 첫 기록으로 인정한다?)
```

**"비교할 값이 없기 때문에 그냥 첫 기록으로 인정한다"** — 05번의 답도 이 문장입니다.

### 문제 05 — `find_best_branch`

4장에서 대부분 다뤘으니 여기서는 나머지를 짚습니다.

#### 역할표에 두 줄이 비어 있습니다

```
# 변수 이름 | 담기는 것 | 시작값 | 시작값의 이유 | 어느 반복문 안/밖에서 만드는가
#i_sum     | 현재 지점의 합계 |0 | 지점의 순이익을 처음부터 하나씩 더하기 위해 | 바깥 반복문 안
#count     |개월 수 | 0 | 지점의 개월 수를 처음부터 하나씩 세기 위해 | 바깥 반복문 안
#          |          |       |              |
```

**적으신 두 줄은 정확합니다.** 특히 마지막 칸의 `바깥 반복문 안` 이 정확해요. 이게 이 문제의 핵심 판단이었고, 코드에서도 정확히 그 자리에 두셨습니다.

```python
    for branch in branches:
        i_sum = 0        # 지점이 바뀔 때마다 새로 0
        count = 0
```

비어 있는 건 **최고 평균 변수와 최고 지점 번호 변수** 두 줄입니다. 그리고 그게 정확히 막히신 지점이고요.

> **역할표를 채우다가 못 채우는 줄이 나오면, 거기가 막힐 지점입니다.**
> 코드를 치기 전에 그걸 알 수 있다는 게 이 칸의 목적이에요.
> 그때 바로 질문하시면 됩니다. *"평균끼리 비교하려면 변수가 몇 개 필요한가요?"* 처럼요.



#### `avg` 이름

`avg` 는 좋은 이름입니다. 다만 `i_sum` 과 `i` 는 짚고 갑니다.

```python
        for i in branch:
            i_sum = i_sum + i
```

`i` 는 관례적으로 **인덱스**를 뜻하는데, 여기서는 **순이익 값**이 들어갑니다. 04번에서 `i` 와 `profits[i]` 의 차이를 정리하셨으니, 그 구분을 이름에도 적용하시면 좋겠습니다.

```python
        for profit in branch:
            total = total + profit
            months = months + 1
```

**`total = total + profit` 은 "합계에 순이익을 더한다"로 그냥 읽힙니다.** `i_sum = i_sum + i` 는 한 번 더 생각해야 하고요.

그리고 `i_sum` 의 `i` 는 무슨 뜻인지 애매합니다. `branch_total` 이나 `total` 이 낫습니다.



#### 변형 문제

```
# 원본 문제 번호 : 4번
# 바꾼 조건 : 경신한 주의 인덱스와 그때의 순이익을 딕셔너리로 반환한다.
# 예시 입력 : [10, 30, 20, 45, 40]
# 예시 출력 : {0: 10, 1: 30, 3: 45}
```

**검산해 봤습니다. `{0: 10, 1: 30, 3: 45}` 가 정확합니다.**

- 0주차 10: 첫 기록 => 포함
- 1주차 30 > 10: 경신 => 포함
- 2주차 20: 경신 아님
- 3주차 45 > 30: 경신 => 포함
- 4주차 40: 경신 아님

**05번이 막혀 있는데도 변형 문제를 만들고 답까지 정확히 내셨습니다.** 그리고 이 변형은 04번과 01번(딕셔너리 누적)을 합친 형태예요. `result.append(i)` 가 `result[i] = profits[i]` 로 바뀌는 셈입니다.

`무엇이 바뀌는가` 칸에 *"반환 형태가 리스트에서 딕셔너리로 바뀐다"* 라고 정확히 쓰신 것도 좋습니다.

**시간 되시면 직접 코드로 짜보세요.** 04번 코드에서 두 줄만 바꾸면 됩니다.

4. **04번 코드를 열어 놓고 05번의 막힌 자리를 채워 보세요.** `high = profits[0]` 이 무엇을 하는 변수였는지 먼저 확인하시고, 05번에서 같은 역할을 할 변수 두 개(최고 평균, 최고 지점 번호)를 만드세요.

## 8. 마지막으로

01~02번 피드백에서 준서 님 상태를 이렇게 정리했습니다.

> 맞는 답을 쓰면서 확신이 없으신 겁니다. 그리고 확신이 없으니까 GPT에 확인을 받으러 가시고,
> 확인을 받고 나면 그게 "내가 알아낸 것"이 아니라 "GPT가 알려준 것"으로 기록됩니다.

**04번에서 그 흐름이 끊어졌습니다.**

같은 실수(`i` 에 값이 들어가는 줄 알았던 것)를 또 하셨는데, 이번엔 GPT를 안 부르고 1트에서 2트로 넘어가면서 스스로 잡으셨어요. 그리고 회고에 *"profits[i]를 써야 실제 값이 나온다는 것을 이해햄"* 이라고 쓰셨습니다.

**"이해함"** 이 중요합니다. "알려줬음"이 아니라.

그리고 05번에서도 GPT를 안 쓰셨습니다. 막힌 상태로 제출하셨는데, **그게 GPT 코드를 붙여넣고 정답을 내는 것보다 낫습니다.** `[내생각]` 블록에 설계를 다섯 줄로 적어 두셨고, 그 설계대로 절반을 짜셨고, 어디서 막혔는지를 `##### 여기서 막혔어요` 로 표시해 두셨거든요. **이 문서의 4장 전체가 그 표시 덕분에 쓰였습니다.**

남은 건 3장의 그 한 가지입니다. **표와 코드를 대조하는 것.**

세 주 연속 같은 이야기를 드리는 이유는, 준서 님의 강점이 정확히 거기 있기 때문입니다. 다섯 명 중 손 추적표를 가장 꾸준히, 가장 정확하게 그리시는 분이에요. 1주차에도 그랬고 이번에도 그렇습니다. 05번 표는 최고 평균과 최고 지점 번호까지 완벽하게 채워져 있고, 그건 이 문제의 답을 이미 손으로 풀었다는 뜻입니다.

**그 표를 답안지로 쓰세요.** 코드를 짠 뒤에 표를 옆에 놓고, 회차 수가 맞는지, 값이 채워지는 자리가 같은지 한 줄씩 보시면 됩니다.
