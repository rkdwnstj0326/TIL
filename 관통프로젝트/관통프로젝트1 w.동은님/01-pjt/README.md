# 📚 01-pjt 도서 데이터 분석 프로젝트

## 1. 📌 프로젝트 개요

이번 프로젝트는 JSON 형식으로 제공된 도서 데이터를 Python으로 읽고, 필요한 정보를 추출·분류·집계·정렬한 뒤 새로운 JSON 파일로 저장하는 프로젝트입니다.

두 명이 약 6시간 동안 함께 진행했으며, 프로젝트는 A, B, C 단계로 구성되어 있었습니다.

- **A 단계**에서는 20권의 도서 데이터를 활용해 제목 추출, 평균 계산, 딕셔너리 생성, 가격 범위별 분류를 구현했습니다.
- **B 단계**에서는 500권의 도서 데이터를 활용해 조건에 맞는 책을 찾고, 출판사와 카테고리별 통계를 계산하고, 날짜와 할인율을 기준으로 정렬했습니다.
- **C 단계**에서는 2,000권의 도서 데이터와 여러 JSON 파일을 활용해 월별 통계를 계산하고, 데이터를 새로운 구조로 재구성하여 JSON 파일로 저장했습니다.

이번 프로젝트의 핵심은 단순히 JSON 파일을 출력하는 것이 아니라, 문제의 요구사항에 맞게 데이터 구조를 이해하고 필요한 형태로 다시 가공하는 것이었습니다.

## 2. 🛠️ 단계별 구현 과정

### 🅰️ A 단계

A 단계에서는 `books_20.json`의 데이터를 이용하여 Python의 기본 문법과 자료구조를 연습했습니다.

책 제목과 가격, 고객 리뷰 순위처럼 필요한 값만 리스트에 저장했고, 평균은 `sum()`과 `len()`을 활용하여 계산했습니다. 또한 책 제목과 작가를 딕셔너리로 연결하고, 정가에 따라 도서를 세 가지 가격 범위로 분류했습니다.

A 단계에서 어려웠던 점은 JSON 전체 구조를 파악하는 것이었습니다. 실제 도서 목록이 최상위에 바로 있는 것이 아니라 `item` key 안의 리스트에 들어 있었기 때문에, 데이터가 어떤 구조로 구성되어 있는지 먼저 확인해야 했습니다.

---

### 🅱️ B 단계

B 단계에서는 `books_500.json`을 활용하여 더 많은 데이터를 조건에 따라 검색하고 통계를 계산했습니다.

카테고리에 `'어린이'`가 포함되지 않은 책을 찾고, 출판사별 도서 수와 카테고리별 평균 가격을 계산했습니다. 또한 출판일을 기준으로 최신 도서를 정렬하고, 정가와 판매가를 이용해 할인율이 높은 도서를 찾았습니다.

B 단계에서 가장 어려웠던 부분은 파일 경로와 JSON 자료형이었습니다. 처음에는 `data['item']`으로 접근했지만, 실제 `books_500.json`은 최상위가 리스트여서 자료형 오류가 발생했습니다. 또한 상대경로는 Python 파일 위치가 아니라 터미널의 현재 작업 위치를 기준으로 해석된다는 점도 직접 오류를 겪으며 이해했습니다.

---

### 🅲 C 단계

C 단계에서는 `books_2000.json`과 `series_items` 폴더를 활용하여 데이터를 새로운 형태로 재구성했습니다.

출판일에서 월을 추출하여 월별 평균 가격을 계산했고, 카테고리 ID를 기준으로 도서를 분류하여 `category_books.json` 파일을 생성했습니다. 또한 여러 폴더에 흩어진 시리즈 도서 JSON 파일을 찾아 하나의 `series.json` 파일로 병합했습니다.

C 단계는 중첩 딕셔너리 구조와 파일 저장 과정이 복잡해 가장 어려웠습니다. 생성형 AI의 도움을 일부 받았지만, 생성된 코드를 그대로 사용하지 않고 실제 데이터의 key, 파일 경로, 결과 구조가 명세서와 일치하는지 확인하면서 수정했습니다.

## 3. 🤝 협업 과정에서 어려웠던 점

이번 프로젝트는 두 명이 같은 저장소에서 각자의 브랜치를 만들어 작업했습니다.

브랜치를 나누어 사용한 덕분에 서로의 작업이 바로 섞이지 않았고, 각자 맡은 파일을 수정한 뒤 `add`, `commit`, `push`하는 방식으로 협업할 수 있었습니다.

다만 두 사람의 자리가 떨어져 있어 실시간으로 소통하기 어려웠던 점이 가장 아쉬웠습니다. 기능을 나누어 작업했지만 서로가 어느 단계까지 진행했는지, 어떤 오류가 발생했는지 바로 공유하기 어려웠습니다.

특히 같은 프로젝트를 진행하면서도 각자 작성한 코드의 실행 위치나 상대경로가 다르게 설정되어 있어, 나중에 코드를 합칠 때 실행 방식이 통일되지 않은 부분도 있었습니다. 역할만 나누는 것뿐 아니라 파일 경로와 실행 방식, 결과 형식까지 미리 합의했어야 했다고 느꼈습니다.

## 4. 🔧 개선할 점

다음 관통 프로젝트에서는 팀원들과 더 자주 소통하면서 진행하고 싶습니다.

프로젝트 시작 전에 전체 명세서를 함께 읽고, 각자 맡을 기능뿐 아니라 다음 내용도 미리 정해야 할 것 같습니다.

- 어떤 폴더에서 코드를 실행할지
- 파일 경로를 어떤 방식으로 통일할지
- 변수명과 출력 형식을 어떻게 맞출지
- 작업 진행 상황을 언제 공유할지
- merge 전에 서로의 코드를 어떻게 확인할지

또한 이번 C 단계에서는 난도가 높아 생성형 AI에 비교적 많이 의존했습니다. 다음에는 바로 전체 코드를 요청하기보다, 먼저 문제를 작은 단계로 나누고 직접 작성할 수 있는 부분까지 작성한 뒤 막히는 부분만 도움을 받으려고 합니다.

생성형 AI가 작성한 코드도 실제 데이터 구조와 맞지 않을 수 있기 때문에, 코드의 각 줄이 어떤 역할을 하는지 이해하고 직접 검증하는 과정을 더 중요하게 생각해야겠습니다.

## 5. 🌱 새롭게 배운 점

### 🐍 Python과 데이터 처리

- `Path` 객체를 이용해 파일 경로를 다룰 수 있다는 점
- 상대경로는 현재 작업 디렉터리를 기준으로 해석된다는 점
- `json.load()`로 JSON 파일을 Python 객체로 변환할 수 있다는 점
- JSON 파일마다 최상위 구조가 리스트 또는 딕셔너리로 다를 수 있다는 점
- 딕셔너리로 항목별 개수와 합계를 누적할 수 있다는 점
- 중첩 딕셔너리와 리스트를 이용해 데이터를 새로운 구조로 만들 수 있다는 점
- `sorted()`의 `key`에 `lambda`나 함수를 전달할 수 있다는 점
- `datetime.strptime()`으로 문자열을 날짜 객체로 변환할 수 있다는 점
- `rglob()`으로 하위 폴더의 JSON 파일까지 검색할 수 있다는 점
- `json.dump()`로 가공한 데이터를 새로운 JSON 파일로 저장할 수 있다는 점

### 🚨 오류 해결

오류가 발생했을 때 무조건 코드를 다시 작성하기보다, 현재 작업 경로와 실제 파일 위치, 변수의 자료형을 먼저 확인해야 한다는 점을 배웠습니다.

특히 다음 오류를 통해 리스트는 문자열 key로 접근할 수 없다는 점을 확실히 이해했습니다.

### 🌿 Git과 협업

이번 프로젝트에서는 같은 저장소 안에서 각자의 브랜치를 만들어 작업했습니다.

- 같은 저장소에서도 브랜치를 나누어 각자의 작업을 분리할 수 있다는 점
- `git add`는 변경 사항을 커밋 대상으로 올리는 명령어라는 점
- `git commit`은 작업 내용을 하나의 기록으로 남기는 과정이라는 점
- `git push`는 로컬 저장소의 커밋을 원격 저장소에 올리는 과정이라는 점
- `git status`를 통해 현재 브랜치와 변경 사항, 원격 저장소와의 동기화 상태를 확인할 수 있다는 점
- 협업에서는 코드 작성뿐 아니라 작업 상황과 실행 방식을 공유하는 것도 중요하다는 점

브랜치를 나누어 작업하면서 서로의 코드가 바로 섞이지 않도록 관리할 수 있었고, 각자 맡은 작업을 커밋 단위로 기록할 수 있었습니다.

다만 브랜치를 나누는 것만으로 협업이 완성되는 것은 아니었습니다. 서로 어떤 파일을 수정하고 있는지, 현재 어느 단계까지 진행했는지, 코드를 어느 위치에서 실행해야 하는지 계속 공유해야 충돌과 혼란을 줄일 수 있다는 점을 배웠습니다.

### 🤖 생성형 AI 활용

C 단계는 A와 B 단계보다 데이터 구조와 구현 과정이 복잡하여 생성형 AI의 도움을 일부 활용했습니다.

생성형 AI는 코드를 대신 완성해주는 도구라기보다, 문제 해결 방향을 제안해주는 보조 도구라는 점을 배웠습니다.

생성된 코드가 오류 없이 실행된다고 해서 바로 완성된 것은 아니었습니다. 명세서의 요구사항과 실제 JSON 데이터의 구조가 일치하는지 확인하고, 코드에서 사용하는 key와 파일 경로가 올바른지 직접 검토해야 했습니다.

또한 생성된 코드의 각 줄이 어떤 역할을 하는지 이해하지 못한 상태로 사용하면, 오류가 발생했을 때 원인을 찾기 어렵다는 점도 느꼈습니다.

다음 프로젝트에서는 먼저 요구사항을 작은 단계로 나누고 직접 작성할 수 있는 부분까지 구현한 뒤, 막히는 부분을 구체적으로 질문하는 방식으로 생성형 AI를 활용하고자 합니다.

## 6. ✍️ 회고

이번 프로젝트를 통해 수업에서 따로 배웠던 리스트, 딕셔너리, 반복문, 조건문, 함수, 파일 입출력이 실제 문제에서는 함께 사용된다는 점을 경험했습니다.

A 단계에서는 기본적인 데이터 추출과 평균 계산을 연습했고, B 단계에서는 더 많은 데이터를 대상으로 조건 검색, 집계와 정렬을 수행했습니다. C 단계에서는 데이터를 새로운 구조로 재구성하고 실제 JSON 파일로 저장하면서 단계별로 난도가 높아지는 흐름을 경험했습니다.

가장 기억에 남는 부분은 파일 경로와 JSON 자료형 때문에 발생한 오류를 직접 해결한 과정입니다. 처음에는 오류가 발생하면 코드 전체가 잘못된 것처럼 느껴졌지만, 현재 작업 위치와 실제 파일 경로, 변수의 자료형을 하나씩 확인하면서 원인을 찾을 수 있었습니다.

특히 `books_20.json`과 `books_500.json`의 최상위 구조가 서로 다르다는 점을 통해, JSON 파일을 사용할 때는 먼저 데이터가 리스트인지 딕셔너리인지 확인해야 한다는 점을 배웠습니다.

협업에서는 브랜치를 나누어 작업한 경험이 의미 있었습니다. 두 명이 같은 저장소를 사용하면서도 각자의 작업 공간을 분리할 수 있었고, 커밋과 push를 통해 작업 내용을 기록할 수 있었습니다.

다만 자리가 떨어져 있어 서로의 진행 상황을 충분히 공유하지 못한 점은 아쉬웠습니다. 각자 맡은 기능을 구현하는 데 집중하다 보니 상대방이 어떤 부분에서 어려움을 겪고 있는지 바로 확인하기 어려웠고, 파일 경로나 실행 방식도 완전히 통일하지 못했습니다.

다음 관통 프로젝트에서는 시작할 때 역할만 나누는 데서 끝내지 않고, 중간중간 진행 상황을 공유하고 서로의 코드를 확인하면서 진행하고 싶습니다. 파일 경로, 실행 위치, 출력 형식과 같은 공통 기준도 미리 정해두고 작업할 계획입니다.

미래에 이 프로젝트를 다시 보게 된다면, 단순히 어떤 코드를 작성했는지만 확인하는 것이 아니라 파일 경로 오류와 자료형 오류를 어떤 방식으로 해결했는지, 협업 과정에서 무엇이 부족했는지를 함께 떠올리고 싶습니다.

이번 프로젝트를 통해 코드를 작성하는 것만큼 데이터 구조를 이해하고, 오류를 분석하고, 팀원과 작업 상황을 공유하는 과정도 중요하다는 점을 배웠습니다.
