# Phase 0 실제 데이터 검증 결과

검증일: 2026-10-22. 사용자 원문 명세는 `docs/PROJECT_SPEC.md`로 보존했다.

**결론: 개인 교육·연구용 로컬 분석과 사례 검색을 시작할 데이터 경로는 확보했다.**
공개 원문 재배포 허락, 전체 AI 기능, 생성 정확성, 독립 검색 성능 검증까지 끝난 것은 아니다.

민원 표는 렌더링한 원본 이미지와 대조했다. 원본과 수집 URL/수집일/SHA-256은 로컬 캐시에 보존했다.

## 2. 통계 정합성

- 권역/기간 관측값 28개, 회사/분기/분류축 관측값 65개: 총 93개.
- 부분합, 권역 구성, 분류축별 총민원 일치, 관측 키 유일성, 음수/결측 검사: 30개 통과.
- 하나 2026Q1 PDF와 2026Q2 HTML의 전분기 수치: 13개 분류 행의 건수·환산건수 모두 일치.
- 두 회사의 공통 기간은 2026Q1, 2026Q2다.
- 최신 공시의 총민원은 하나 75건, 신한EZ 89건이다. 이는 회사별 표의 접수경로 축에서 확인했다.
  두 값을 회사의 우열/소비자 피해율 순위로 해석하지 않는다.
- 연간과 반기는 분리하고 2025H1↔2026H1 또는 2024↔2025만 증감 비교한다.
- 상품·유형·접수경로는 같은 모집단의 다른 분류축이다. 축간 합산을 금지한다.
- 환산건수 분모는 분기말 회사/상품 보유계약이다. 실제 보유계약 원수는 확보하지 않았다.
- 환산값의 ‘-’는 결측으로 보존했다. 상품별 환산값을 더하거나 분모를 역산하지 않았다.

세부 정의의 한계: 하나 최신 공시는 중복/반복·단순상담·질의 ‘등’ 제외를 기재하고,
신한EZ는 자율조정·B2B·소송 관련 제외까지 명시한다. 표현이 완전히 같지 않아
모든 제외 기준이 동일하다고 단정하지 않았다. 개인별/상품별 위험 구성을 보정한 비교도 아니다.
현재 화면은 회사별 현황을 별도로 탐색하며 나쁜 회사 순위를 만들지 않는다.

## 3. 사례 품질과 결측

| 항목 | 결과 |
|---|---:|
| 게시 문서 / 고유 ID | 70 / 70 |
| 정규화 본문 해시 유일 | 70 |
| 고유 제목 | 69 |
| 민원내용·쟁점·처리결과 보유 | 각 70/70 |
| 추출 문단 수 | 593 |
| 별도 확정한 회사명 / 결정일 | 각 0/70 |
| 분리된 소비자 주장 / 회사 주장 / 판단 / 결정주문 필드 | 각 0/70 |

‘분리된 판단/결정주문’이 없다는 말은 처리 근거가 없다는 뜻이 아니다.
공식 페이지가 판단 근거와 결론을 `처리결과`에 함께 적었으므로 통합 원문 필드로 보존했다.
별도 소제목이 없는 값을 AI로 채워 구조화 완료라고 주장하지 않았다.
이 문서들은 기관의 공개 사례 설명이며 정식 조정결정서 전문 70건과 구분한다.

문서 분포: 손해보험(일반/책임/재물/운전자 등) 25, 자동차 20, 실손 10,
질병·상해·간병 9, 생명 3, 보험 일반 3. 이 분포는 **공개 문서의 구성**이며 실제 민원 발생 분포가 아니다.
초기 최신 목록만 수집했을 때 자동차 편중이 커, 실손·질병·생명·설명의무 사례 목록을 추가 확인했다.
여전히 공개 편집·게시 선택과 부지급 사례 중심의 편향이 있다. 발생률/보상률 예측용 학습 자료로 사용할 수 없다.

같은 제목의 백내장 사례 `fss_case_162`와 `fss_case_71`은 다른 게시일의 문서다.
별도 원본으로 보존하고 검색 결과에서는 최신 게시본을 우선했다.
동일한 실제 사건인지 확인할 개인/사건 식별 정보가 없으므로 ‘독립 사건 70건’이라고 표현하지 않는다.
다른 유사 주제의 재서술까지 모두 제거했다는 주장도 하지 않는다.

게시일 범위는 2024-07-11~2026-01-16이다. 게시일을 결정일로 대체하지 않았다.
익명 사례를 하나/신한EZ 사건으로 연결하지 않는다. 향후 유형 연결도 ‘관련 사례’로만 표현한다.

## 4. 실제 검색·인용 경로 확인

외부 API 없이 한국어 문자 2~4gram TF-IDF 검색 기준선을 구현했다.
아래 5개 쟁점은 개발자가 원문을 보며 골라 작은 스모크 검사를 실행했다.

| 질문 쟁점 | 기대 문서 | 실제 상위 5건에 포함 |
|---|---|---|
| 백내장·다초점 인공수정체 | 162 또는 71 | 예 · 최신 중복 제한 후 162 |
| 건강검진 의심소견·고지의무 | 62 | 예 |
| 유니버셜 종신보험·해피콜 | 63 | 예 |
| 연금 예상배당금·가입설계서 | 130 | 예 |
| 진료비 영수증 외 추가 서류 | 73 | 예 |

모든 발췌의 문서 ID/문단/실제 문자열 존재를 확인했다.
없는 문서·없는 문단·다른 문서 문장·변조 문자열 인용을 거부하는 검사도 통과했다.
출처 번호가 맞는 것과 답변 주장을 실제로 뒷받침하는 것은 다른 평가다.
현재는 생성 답변이 없으므로 인용 의미 일치/근거 부족 보류/답변 정확성을 평가하지 않았다.
5개 스모크 질문을 독립 정답셋이나 Recall@5 최종 성능으로 쓰지 않는다.

## 5. 수집·캐시·개인정보 검사

- 등록한 원본 문서 파일 78개의 실제 SHA-256을 대조했다. 불일치 0개.
- 78개를 실제 운영 캐시로 다시 조회했다. 캐시 적중 78개, HTTP 재호출 0회.
- URL 캐시는 수집 성공 후 저장한다. 캐시 기록만 있고 원본이 없거나 변조되면 중단한다.
- robots 금지/외부 호스트 리다이렉트 차단, 429/5xx 재시도, Retry-After 두 형식은 오프라인 시험했다.
  실제 서버에 오류를 유발하여 재시도를 시험한 것은 아니다.
- 공개 사례 본문 70개에 이메일/전화번호/주민번호 유사 패턴을 검사했다. 해당 패턴 검출 0건.
  실명·간접 식별정보 완전 제거를 검증한 것은 아니다. 공개 전 사람 검수가 필요하다.
- 한국소비자원은 robots 전체 금지로 자동 수집하지 않았다. 소비자24의 제한도 우회하지 않았다.

원본 이상 징후: 2026년 상반기 금감원 PDF 1쪽의 배포 연도 표기는 보고서 제목/보도일과 맞지 않는 부분이 있다.
원문을 고치지 않고 기록했다. 분석 기간은 제목·표 머리글의 실제 비교 기간에서 읽었다.
사례 제목의 오탈자 역시 원문을 보존했다.

## 6. 테스트와 초기 화면

`pytest`: 17개 통과. 실제 데이터 정합성/인용/캐시와 네 화면의 이동/기간 변경/
회사 선택/상품 분류/검색/결과 없음 안내를 검사했다. 자동 화면 시험 중 외부 HTTP 요청은 차단했다.
`pip check`: 의존성 충돌 없음. Python 3.12.10, Streamlit 1.62.0, Plotly 7.1.0을 전용 가상환경에 설치했다.

로컬 Streamlit 서버의 건강 확인(`ok`)과 두 번째 실행 시 같은 PID/포트 재사용을 별도로 확인했다.
브라우저의 실제 픽셀/모바일 화면/사용자 사용성 평가는 아직 별도 수행 전이다.
README의 데이터 준비 명령도 실제 실행해 종료 코드 0을 확인했다. 이 재실행은 기존 캐시를 사용했으며
빈 환경에서 인터넷 재수집을 처음부터 한 번 더 반복한 것은 아니다.
pytest 기본 임시 경로의 Windows 실행 환경 문제는 프로젝트 내부 `.pytest_tmp`를 사용하도록 조정했다.

## 7. 범위 확정과 다음 단계

기술 데이터 게이트는 통과했다. 이 근거로 보험 우선·두 회사 분기 공시·공개 사례 검색 범위를 정했다.
초기 통계 대시보드와 문자 검색 검수 화면을 구현했다. 세부 결정은 `docs/SCOPE_DECISION.md`에 있다.

아직 남은 작업: 한국어 의미 임베딩/ChromaDB, LangGraph+실제 GMS 생성,
통계/사례 기반 개선 보고서, 독립 30문항 평가와 인용 의미/보류 검증,
검수된 라벨이 있는 경우에 한한 분류 모델 비교, 공개 이용 조건 확인, 시연 영상.
기존 리뷰 분석 프로젝트의 평가 결과나 GMS 생성 결과를 이 프로젝트 성적으로 가져오지 않았다.

원문 재배포의 공개 게이트는 통과하지 않았다. 현재 원문·가공본문·PDF 증거는 로컬/Git 제외 경로에만 둔다.
