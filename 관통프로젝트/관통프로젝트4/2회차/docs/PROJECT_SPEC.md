# FinVOC Korea AI
## 국내 금융민원 분석 및 분쟁조정 의사결정 지원 워크벤치

**프로젝트 유형:** 개인 AI·데이터 분석 포트폴리오  
**개발 언어:** Python  
**서비스 언어:** 한국어  
**주요 기술:** Pandas, scikit-learn, ChromaDB, RAG, LLM, Streamlit  
**개발 방식:** 데이터 검증 우선, 단계별 기능 구현 및 성능 평가

---

# 1. 프로젝트 개요

## 1.1 프로젝트 정의

국내 금융감독기관과 금융회사가 공개한 실제 민원 통계 및 분쟁조정 사례를 분석해 반복적으로 발생하는 금융소비자 문제를 파악하고, 관련 조정 사례와 판단 근거를 검색하여 담당자의 의사결정을 지원하는 AI 워크벤치를 개발한다.

## 1.2 프로젝트 목적

금융서비스에서 발생하는 고객 불만을 데이터로 파악하고, 유사 분쟁 사례를 근거로 담당자가 문제를 검토할 수 있도록 지원한다.

기존의 단순한 금융 챗봇과 차별화하여 다음 기능을 하나의 서비스에서 제공한다.

1. 금융서비스별 민원 현황 및 반복 문제 분석
2. 금융회사별 공개 민원 통계 비교
3. 유사 금융분쟁 사례의 RAG 기반 검색
4. 실제 분쟁조정 결과와 판단 근거 확인
5. AI 기반 주요 문제 및 개선 검토 보고서 생성
6. 검색 정확도와 AI 답변 신뢰성 평가

## 1.3 핵심 사용자

- 금융회사 고객경험(CX) 담당자
- 고객 불만 및 민원 관리 담당자
- 금융서비스 기획자
- 금융소비자보호 담당자
- 데이터 분석 및 업무 개선 담당자

## 1.4 핵심 사용자 시나리오

금융회사 담당자가 특정 금융서비스의 민원 발생 현황을 확인하고, 증가하는 문제 유형을 선택한다.

시스템은 실제 공개 통계를 분석하고, 관련 분쟁조정 사례를 검색한다. 담당자는 소비자 주장, 금융회사 주장, 조정기관의 판단 및 결과를 확인한다.

이후 AI가 관련 근거를 바탕으로 개선 검토 사항을 정리한 보고서를 생성한다.

# 2. 데이터 수집 및 활용 설계

## 2.1 데이터 수집 원칙

본 프로젝트는 실제 한국 금융 데이터를 사용한다.

가상의 금융회사, 민원 원문, 분쟁조정 결과, 민원 발생 건수를 실제 데이터처럼 사용하지 않는다.

**데이터를 먼저 확보하고 그 데이터에서 구현 가능한 기능을 확정한다.**

초기 데이터 검증을 완료하기 전까지 대시보드에 임의의 통계 수치를 넣지 않는다.

**주의:** 분쟁조정 사례는 전체 금융민원의 대표 표본이 아니다. RAG의 사례 근거 자료로 활용하되, 발생 빈도 계산의 모집단으로 사용하지 않는다.

## 2.3 초기 개발 범위

처음부터 은행, 카드, 보험, 증권 전체를 분석하지 않는다.

**1차 구현: 보험 민원 중심**

- 생명보험
- 손해보험
- 보험금 지급 관련 민원
- 계약 및 판매 관련 민원
- 실손보험 관련 분쟁조정 사례

**2차 확장**
- 은행 및 예금
- 대출
- 신용카드
- 금융투자

초기에는 공개 통계가 확보된 2~3개 보험회사를 선정하고, 분쟁조정 사례는 30건 이상 확보하는 것을 데이터 검증 목표로 한다.

이는 개발 목표치이며 현재 확보된 데이터 수량이 아니다.

## 2.4 필수 데이터 검증

개발 시작 전 다음을 확인한다.

- 실제 통계자료의 다운로드 가능 여부
- 표의 연도 및 분기 구분
- 동일한 기준으로 비교할 수 있는 공시자료의 수
- 실제 분쟁조정 사례 원문 접근 가능 여부
- 문서에서 텍스트 추출 가능 여부
- 이용허락, 출처 표시 및 자동 수집 허용 범위
- 개인정보 포함 여부
- 중복 사례 존재 여부
- 사례의 사실관계, 판단, 결과 분리 가능 여부

자동 수집이 허용되지 않거나 기술적으로 불가능한 경우 공식 자료를 직접 다운로드해 제한된 범위에서 처리한다. 이용 조건을 우회하지 않는다.

### 반드시 지킬 데이터 연결 원칙

금융회사별 민원 통계와 분쟁조정 사례는 서로 다른 데이터다.

분쟁조정 사례에서 특정 회사가 확인되지 않는다면 해당 사례를 임의로 특정 회사의 민원에 연결하지 않는다.

통계로 확인된 반복 문제와 내용이 비슷한 사례를 연결할 때는 **'관련 사례'**라고 표시하고, **'해당 회사의 실제 처리 사례'**라고 표시하지 않는다.

# 3. 핵심 기능 상세 명세

## 기능 1. 금융민원 현황 대시보드

### 목적

사용자가 금융서비스에서 자주 발생하는 민원 유형과 변화 추이를 직관적으로 파악하도록 한다.

### 입력

- 금융 권역
- 금융서비스 유형
- 금융회사(해당 데이터가 존재할 경우)
- 분석 기간
- 민원 유형

### 주요 화면

**상단 요약 지표**
- 분석 대상 민원 건수
- 전기 대비 증감률
- 가장 많은 민원 유형
- 가장 많이 증가한 민원 유형

**시각화**
- 기간별 민원 발생 추이: 꺾은선그래프
- 민원 유형별 비중: 가로 막대그래프
- 회사별 민원 유형 비교: 누적 막대그래프
- 전기 대비 유형별 증감: 비교표

모든 숫자는 실제 집계 데이터로부터 계산한다.

### 구현 방법

Python Pandas로 데이터를 정제하고 집계한다.

Streamlit과 Plotly로 차트를 구성한다.

사용자가 필터를 바꾸면 해당 조건의 데이터를 다시 집계한다.

### 주의사항

서로 다른 회사의 민원 건수를 비교할 때 회사 규모나 보유계약 건수를 고려해야 한다.

동일한 기준의 환산건수가 없으면 단순 건수만으로 금융회사 우수·부실 순위를 제공하지 않는다.

## 기능 2. 반복 민원 및 문제 유형 분석

### 목적

특정 서비스에서 어떤 문제가 반복되고 있는지 파악하고 개선 검토 대상을 선정한다.

### 주요 기능

1. 유형별 민원 발생 건수 계산
2. 전체 민원 대비 유형별 비중 분석
3. 전기 대비 유형별 증가율 계산
4. 증가 폭이 큰 문제 자동 표시
5. 반복적으로 높은 비중을 차지하는 문제 표시

### 분석 방식

통계자료에 실제로 있는 분류체계를 우선 사용한다.

예를 들어 보험회사의 민원 공시에서 판매, 유지, 지급 등의 유형이 제공된다면 이 구분을 기준으로 분석한다.

공개 통계가 세부 불만 유형을 제공하지 않는 경우 AI가 임의로 세부 건수를 생성해서는 안 된다.

### 결과 화면

**민원 개선 검토 목록**

| 항목 | 표시 내용 |
|---|---|
| 서비스 | 실손보험 등 실제 서비스 분류 |
| 민원 유형 | 지급, 유지 등 |
| 현재 기간 건수 | 실제 집계값 |
| 이전 기간 대비 변화 | 실제 계산값 |
| 검토 우선순위 | 사전에 정의한 기준으로 산출 |
| 관련 사례 | 동일·유사 문제에 해당하는 공개 분쟁조정 사례 |

검토 우선순위는 발생 빈도와 변화 정도를 반영한 내부 분석 지표이며 실제 피해 심각도나 법률적 책임을 판단하는 지표가 아니다.

## 기능 3. 한국어 금융분쟁 RAG 검색

### 목적

사용자가 자연어로 질문하면 실제 국내 분쟁조정 사례에서 관련 내용을 찾아 근거와 함께 설명한다.

### 예시 질문

- "실손보험금 지급이 거절된 사례를 찾아줘."
- "보험 가입 전에 질병을 진단받은 경우 어떤 분쟁이 발생했어?"
- "보험금 지급 관련 분쟁에서 조정기관은 어떤 사실을 중요하게 판단했어?"
- "금융소비자에게 유리한 결론과 불리한 결론이 나온 사례를 각각 비교해줘."

### 처리 과정

**1단계 — 질문 분석**

사용자 질문에서 금융서비스, 문제 유형, 주요 키워드와 검색 조건을 추출한다.

**2단계 — 관련 문서 검색**

- 한국어 텍스트 임베딩
- ChromaDB 벡터 검색
- 키워드 검색
- 필요 시 두 검색 결과를 결합한 하이브리드 검색

**3단계 — 근거 문서 추출**

유사한 분쟁조정 사례를 검색하고 사례별 사건개요, 판단, 처리 결과를 구분한다.

**4단계 — LLM 답변 생성**

검색된 문서에 근거하여 질문에 답한다.

AI는 실제 존재하는 사례만 인용한다.

**5단계 — 근거 표시**

답변 아래에 다음 정보를 표시한다.

- 실제 사례 제목
- 제공 기관
- 분쟁 쟁점
- 조정 결과
- 원문 링크
- PDF인 경우 해당 페이지

### 필수 제한사항

- 실제 근거가 없는 경우 추측하지 않는다.
- 서로 다른 사례의 사실관계를 혼합하지 않는다.
- 과거 사례를 현재 모든 분쟁에 그대로 적용할 수 있다고 주장하지 않는다.
- 개별 사건의 법률적 결과를 확정적으로 예측하지 않는다.

## 기능 4. 분쟁조정 사례 비교

### 목적

비슷한 문제가 어떤 상황에서 다른 판단을 받았는지 비교할 수 있도록 한다.

### 화면 구성

사용자가 사례 두 개를 선택하면 아래 항목을 나란히 표시한다.

| 비교 항목 | 사례 A | 사례 B |
|---|---|---|
| 금융서비스 | 원문 기준 | 원문 기준 |
| 분쟁 쟁점 | 원문 기준 | 원문 기준 |
| 소비자 주장 | 확인된 내용 | 확인된 내용 |
| 금융회사 주장 | 확인된 내용 | 확인된 내용 |
| 판단 근거 | 확인된 내용 | 확인된 내용 |
| 조정 결과 | 확인된 내용 | 확인된 내용 |

AI가 두 사례의 공통점과 차이점을 설명하도록 구현한다.

단, 해당 문서에서 회사 주장이 공개되지 않았다면 '자료에 명시되지 않음'이라고 표시한다.

## 기능 5. AI 업무 개선 검토 보고서

### 목적

민원 통계와 분쟁조정 근거를 종합해 담당자가 검토할 수 있는 보고서를 생성한다.

### 보고서 구성

**1. 분석 개요**
- 분석 대상
- 분석 기간
- 데이터 출처

**2. 주요 민원 현황**
- 민원 건수 및 비중
- 주요 유형
- 기간별 변화

**3. 반복 문제 분석**
- 자주 발생하는 문제
- 증가한 유형
- 추가 검토가 필요한 항목

**4. 관련 분쟁조정 사례**
- 유사 사례
- 조정기관 판단
- 확인 가능한 처리 결과
- 원문 근거

**5. 개선 검토 제안**
- 고객 안내 강화 필요성
- 약관 설명 및 고지 방식 점검
- 관련 내부 절차 확인
- 추가 데이터 확보 또는 원인 조사 필요성

**6. 분석의 한계**
- 데이터의 시점과 범위
- 확인할 수 없는 정보
- 추가적인 사실 확인이 필요한 부분

### AI 생성 원칙

보고서는 반드시 아래 세 영역을 구분한다.

- **확인된 사실:** 공식 통계나 분쟁조정 문서에서 확인한 내용
- **분석적 해석:** 데이터를 계산하고 비교하여 도출한 내용
- **개선 검토 제안:** 추가 확인이나 내부 검토가 필요한 제안

AI의 추정이나 제안을 공식 분쟁조정 결과처럼 표현하지 않는다.

## 4.2 머신러닝 기능

**선택 기능: 금융분쟁 쟁점 자동 분류**

공개된 분쟁조정 사례의 쟁점을 분류하는 기능을 개발한다.

예시 분류:
- 보험금 지급
- 계약 고지 및 설명
- 계약 유지·해지
- 기타

분류 기준은 확보한 사례와 정답 라벨을 직접 검토한 뒤 확정한다.

### 모델 비교

- 기준 모델: 규칙 기반 분류
- 모델 A: TF-IDF + Logistic Regression
- 모델 B: TF-IDF + Linear SVM
- 추가 비교: LLM 기반 분류

### 평가

- Accuracy
- Macro F1
- 클래스별 Precision 및 Recall
- 혼동행렬
- 오류 사례 분석

공개 분쟁조정 사례가 적다면 억지로 모델 학습을 진행하지 않는다.

실제 사례 수와 라벨 품질이 충분할 때 학습 모델을 추가하고, 그렇지 않으면 규칙 기반 분류와 LLM 분류의 결과를 수작업 검증하는 방식으로 진행한다.

**데이터 품질보다 모델의 개수를 우선하지 않는다.**

## 4.3 RAG 설계

### 문서 전처리

분쟁조정 문서를 다음 단위로 구조화한다.

- 문서 ID
- 사례 제목
- 금융 권역
- 금융상품·서비스 유형
- 사건개요
- 주요 쟁점
- 소비자 및 사업자 주장
- 판단 근거
- 처리 결과
- 원문 URL
- 페이지 또는 문단 위치
- 자료 기준일

문서 내부의 사건개요와 판단 결과를 구분해 저장한다.

### 검색 구조

1. 사용자 질문 입력
2. 금융서비스 유형 파악
3. 임베딩 생성
4. 벡터 검색과 키워드 검색
5. 관련도에 따라 검색 결과 정렬
6. 출처가 확인된 문서 선택
7. LLM 답변 생성
8. 인용 검증 후 사용자에게 출력

### RAG 품질 향상

단순 벡터 검색과 하이브리드 검색의 성능을 비교한다.

질문과 관련 없는 문서가 검색되거나 충분한 근거가 없는 경우 답변 생성을 보류하도록 한다.

# 7. 개발 단계

**가장 먼저 수행할 작업**

1. 금융감독원 금융민원 보고서 확보
2. 금융회사별 민원 공시 파일 확보

이 조건을 충족하지 못하면 전체 시스템을 먼저 개발하지 않는다. 확보된 자료에 맞춰 구현 범위를 조정한다.

# 10. AI 코딩 도구 개발 지침

이 프로젝트는 실제 한국 금융 데이터를 활용한 개인 취업 포트폴리오다.

다음 원칙을 반드시 준수한다.

1. 데이터 확보와 검증을 마치기 전에 전체 서비스를 임의로 구현하지 않는다.
2. 외부 자료의 접근 및 재사용 조건을 확인한다.
3. 가상의 금융회사, 분쟁조정 사례, 민원 통계를 실제 정보처럼 제시하지 않는다.
4. 개발은 데이터 수집 → 분석 → RAG → 보고서 → 성능 평가 순서로 진행한다.
5. 기능을 추가할 때마다 기존 기능에 오류가 발생하지 않는지 테스트한다.
6. AI가 작성한 Python 코드는 초보 개발자가 이해할 수 있도록 각 파일의 역할과 핵심 처리 과정을 한글로 설명한다.
7. 이미 작성한 이전 리뷰 분석 프로젝트는 보존하고 새로운 프로젝트로 분리한다.
8. 최종 결과물은 데이터 분석 능력, AI 기술 구현, 실제 비즈니스 문제 해결 과정이 드러나도록 구성한다.

**최우선 작업은 Phase 0 데이터 검증이다.**

데이터 검증 결과를 정리한 뒤 확보 가능한 데이터에 맞게 최종 구현 범위를 확정한다.
