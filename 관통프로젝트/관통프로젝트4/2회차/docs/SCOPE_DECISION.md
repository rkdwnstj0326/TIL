# 실제 확보 자료를 기준으로 정한 초기 범위

기준일: 2026-10-22. 사용자 명세 `PROJECT_SPEC.md`를 보존하고 그 Phase 0부터 실행했다.
아래 범위는 신규 FinVOC 프로젝트의 범위이며, 기존 과제 제출본을 대체하거나 제출한 것이 아니다.

## 초기 사용자와 문제

보험사 소비자보호/CX 담당자가 공식 공시로 민원 구성을 확인하고,
관련 공개 분쟁 사례의 사실관계와 처리 근거를 찾아 검토할 수 있도록 한다.
회사 내부 민원 원장이나 실제 고객 개인정보는 확보하지 않았다.

## 확보 자료로 가능한 범위

- 보험 우선. 두 손해보험사의 2026년 1·2분기 공시를 사용한다.
- 금감원 권역 통계는 연간끼리 또는 상반기끼리만 추세를 비교한다.
- 민원 유형/상품 분포는 회사별 원문 수치에 한해 계산한다.
- 기관의 공개 보험 사례 70개 문서를 확보했다. 같은 제목의 2게시본은 별도 보존하고 검색에는 최신 1개를 우선한다.
- 초기 사례 검색은 실손·질병·상해·연금·자동차·책임보험 쟁점별 검토를 지원한다.
- 통계와 사례를 연결할 때는 ‘관련 사례’를 제안할 수 있을 뿐, ‘이 회사의 실제 사건’으로 표시할 수 없다.

## 자료가 허용하지 않는 해석

- 70개 게시 문서는 표본 추출된 전체 민원 원장이 아니다. 유형별 게시 빈도는 실제 발생률이 아니다.
- 사례의 회사명/결정일이 별도 확정되지 않았다. 회사별 사례 비교, 승소율/보상률 모델을 만들 수 없다.
- 판단·결과는 원문에서 통합되어 있다. 그 내용을 유지하고, 별도 결정주문/당사자 주장은 추정하지 않는다.
- 두 보험사의 공시 기간과 환산 단위는 맞지만 세부 제외 항목의 문구는 완전히 동일하지 않다.
  하나 최신 공시는 중복·반복/상담·질의 제외 등을 기재하고, 신한EZ는 자율조정/B2B/소송 관련 제외까지 열거한다.
  ‘등’에 모두 포함된다고 추정하여 완전 동등 비교나 순위를 만들지 않는다.
- 회사 전체 보유계약 기준 환산값과 상품별 보유계약 기준 환산값을 합치지 않는다.
- 실제 보유계약 원수는 확보하지 않았다. 반올림된 환산건수에서 분모를 역산해 실제 계약수처럼 표시하지 않는다.

## 다음 단계의 개발 기준

1. 초기 대시보드에서 통계와 출처를 확인할 수 있게 한다. (현재 구현)
2. 한국어 의미 임베딩/ChromaDB 및 문자 검색과 결합한 검색을 구축한다.
3. LangGraph의 검색→생성 흐름에서 허용 근거 ID/문단 인용을 검증한다.
4. 실제 LLM 생성은 사례 조건과 과거/현재의 차이를 보존하고 근거가 없으면 보류한다.
5. 별도 검수한 30문항 정답셋으로 검색을 비교한다. 현재 5문항 스모크 검사는 대체물이 아니다.
6. 개선 보고서는 ‘공식 사실 / 계산 결과 / 검토 가설’을 나누고 실제 기업 조치 결과를 꾸며 넣지 않는다.
7. 유형 분류 모델은 사람 검수 라벨과 학습/평가 분리 조건이 확보된 뒤 진행한다.

## 단계 통과의 의미

`technical_data_gate_passed=true`는 실제 원문과 최소 통계·검색·인용 경로를 확보했다는 의미다.
전체 서비스, 검색 정확도, 법적 판단, 개인정보 완전 익명화, 원문 공개 재배포가 검증되었다는 뜻은 아니다.
`public_reuse_gate_passed=false`를 별도로 기록했다. 현재 앱은 개인 교육·연구용 로컬 검토판이다.

## 보험사 범위 확장 · 2026-10-22

사용자 요청에 따라 공식 협회 공시로 손해보험 17개사, 직접 공시로 교보생명 1개사를 수록했다.
공통 시점은 2026년 2분기이며 원문에서 전분기인 1분기도 확인했다. 기존 2개사의 65개 관측값과
익명 사례 70개를 보존했다. 이 변경은 원래 Phase 0 스냅샷을 덮어쓰지 않고 별도 확장 파일로 구현했다.
생명보험 원문 분류와 즉시연금 제외조건은 별도 표시한다. 새 15개 손해보험사 상품표의 상세 분모는
협회 표/매뉴얼에 명시되지 않아 미확인으로 남기고 상품별 환산값 비교를 보류한다.
익명 사례의 회사별 사건 배정과 회사 우열 순위는 제공하지 않는다. RAG 개발 범위는 위 후속 단계와 같다.
