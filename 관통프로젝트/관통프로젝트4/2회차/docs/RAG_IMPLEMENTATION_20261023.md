# FinVOC Korea — 실제 RAG 구현 및 검증

2026-10-23. 이전 Phase 0 문서는 당시 기록이다. 현재 구현 판정은 이 문서와 최신 요구사항 대조표를 따른다.

## 실제 실행 구조

`config/rag.json` → 한국어 지원 MiniLM(384차원, 실제 상한128토큰) → Chroma 두 컬렉션.

- `items_<설정지문>`: 회사·분기별 메타데이터 1건. 과거 공시를 포함한177개 항목을 미리 색인한다.
- `docs_<설정지문>`: 질문에서 선별·수집한 원문 청크. 회사·분기 항목ID를 필터로 사용한다.
- 임베딩 모델·리비전·청킹·배포 모드가 바뀌면 다른 컬렉션을 사용한다.
- `top_k`, `fetch_k`, MMR lambda와 검색 방법은 설정 파일에서 바꾼다.

```mermaid
flowchart LR
    Q[회사·분기와 질문] --> R[retrieve]
    R --> G[generate]
    G --> V[인용 검사와 사용 출처 표시]
```

LangGraph 실행 노드는 `retrieve`, `generate` 두 개다. 프롬프트는 검색어 추출·문서 선별·답변 생성 세 개다.
JSON의 타입·검색어 길이·허용 문서ID·근거 번호를 검사한다. 원문/이전 대화 속 지시는 자료로 취급한다.

## 질문 시점 수집

1. GMS가 보험 범위와 한국어 검색어를 추출한다.
2. **기존에 확보한 공식 사례 목록 70개**에서 제목/본문 후보를 찾고 GMS가 관련 ID를 선별한다.
   웹 전체 검색이나 새로운 사례 목록의 자동 최신화로 주장하지 않는다.
3. 선택 보험사·분기 자체 공시의 실제 원문 캐시를 검증하고 원문 표 행을 우선 색인한다.
4. 선별 사례는 공식 URL을 `Client.fetch`로 요청한다. 무결성이 확인된 기존 본문 캐시는 재사용한다.
5. 실제 본문을 다시 파싱하고 제목뿐인 문단은 제외한다. 모든 외부 원문을 미리 색인하지 않는다.
6. `항목ID:문서ID:청크순번`으로 upsert한다. DB 존재·해시를 확인한 뒤에만 완료를 기록한다.
7. 선택 항목 메타데이터를 항상 근거1로 넣고, 외부 검색에는 item_id와 이번 선별 문서ID를 적용한다.

자체 공시의 원문 행은 전분기/당분기 열이 함께 있을 수 있다. 선택 기간의 정제값과 기간 라벨을 함께 제공한다.
익명 업계 사례의 실제 사건 회사는 미확인으로 남기며, 검색용 선택 항목ID와 구분한다.

## 한국어 청킹과 검증

실제 토크나이저에서 truncation=128을 확인했다. 제한 없는 별도 토크나이저의 문자 오프셋으로 창을 나눈다.
문단별 모든 창을 색인하고 긴 항목 메타데이터는 모든 창의 평균을 L2 정규화해 1개 벡터로 만든다.
긴 한국어 시험문 전체 문자와 마지막 문장이 포함되는지 검사했다. 임의/해시 벡터는 사용하지 않는다.

## 생성과 보류

GMS 주소/모델은 기존 배포 코드의 관례를 확인해 설정했다. `.env`의 GMS_KEY만 읽으며 다른 프로젝트를 찾지 않는다.
키가 없으면 실제 검색 원문 발췌만 표시한다. 키가 있으면 실제 GMS 응답을 검증 후 보여 준다.
주요 주장에 [1] 형식으로 인용하며 실제 사용한 문서의 제목·유형·발췌·URL·원문 수집일만 표시한다.
번호의 존재는 자동 검사하지만 인용 내용이 주장을 지지하는지의 의미 검수는 별도다.

대표 검증 중 2030년 질문에 2026년 수치로 답한 오류가 있었다. 요청 기간이 근거에 없는지 먼저 검사하고,
생성 모델이 이를 어기면 답변을 거부해 확인 불가로 보류한다. 보고서의 `model_answer_rejected`로 구분한다.
API 오류 2건은 재실행했다. 초기 실패 기록을 전체 로컬 보고서에 보존했다.
